# Performance Budget Guardian addon

Copy this directory to `res://addons/performance_budget_guardian/`, enable **Performance Budget Guardian** in Project Settings > Plugins, and add a `PerformanceBudgetProbe` node to the scene to measure. The node also works when its script is attached directly, including headless runs.

Addon `1.2.0` also adds a read-only **Guardian** main-screen workspace beside Godot's 2D, 3D, Script, Game, and AssetLib buttons. Select it to open the central **Performance Guardian** page; switching away restores the normal workspace without occupying the Inspector, Node, or FileSystem docks. It lists probe readiness for the active scene, recent captures and canonical Guardian/calibration reports, and failed deterministic rules. It never runs captures, Python, budgets, CI, network requests, or AI, and it never calculates a verdict from raw captures.

The workspace scans configured probe output paths, `res://results`, and `res://.performance-guardian`. **Add evidence** accepts project-contained JSON for the current editor session; **Locate** selects visible evidence in Godot's FileSystem dock and **Copy res:// path** copies its portable path. Downloaded CI evidence must first be extracted or copied beneath the project. Absolute paths, traversal, traversed links, unsupported schemas, malformed JSON, files over 8 MiB, and scans beyond 1,000 JSON files are rejected or reported safely.

Capture ordering uses only capture schema v1 `ended_at_utc`. Guardian v1/v2 and calibration v1 reports currently have no canonical report timestamp, so they are placed after timestamped captures and sorted by report type and normalized project path. Filesystem creation and modification times are never treated as evidence time. Raw captures are labeled **Not evaluated**; failed rules come only from canonical Guardian reports, and calibration remains **Proposal only—not an enforced verdict**.

The probe captures engine process/physics time and global memory/object/node monitors after a configurable warmup. It writes raw samples and summaries atomically to a safe `res://` path. It does not measure a project workload directly, perform cleanup assertions, access the network, or require Python or AI.

Because the probe accumulates raw samples during capture, static-memory growth includes probe storage overhead and cannot by itself prove a project memory leak. A memory budget can flag a regression between comparable captures, but comparisons should use the same measured-frame count and sampling interval.

Command-line overrides are `--pbg-profile`, `--pbg-warmup-frames`, `--pbg-measured-frames`, `--pbg-sampling-interval`, `--pbg-output`, `--pbg-run-id`, `--pbg-source-revision`, and `--pbg-auto-quit`. Value-bearing arguments use `--name=value`.

When upgrading the addon, replace the installed addon directory while the plugin is disabled and create a fresh capture with a new run ID. Do not change old capture metadata to claim a newer addon version: result files are evidence of the version that produced them. Historical `1.0.1` and `1.1.0` captures remain schema-compatible with `1.2.0`; `1.0.0` remains unsupported because it lacks the mandatory probe-storage memory limitation.

To remove the addon, remove its probe nodes, disable the plugin, and delete only `res://addons/performance_budget_guardian/`.

Installing the addon is separate from enabling CI. For turnkey Windows CI, also commit the addon, keep an automatically starting probe in the measured scene, commit a schema-v2 or schema-v3 profile budget, ignore `.performance-guardian/`, and call the repository's reusable workflow at an immutable Guardian commit SHA. It installs Godot, runs three isolated captures by default, validates them, applies the project budget, and uploads captures, logs, manifests, and canonical gate JSON. AI investigation is optional and defaults to `never`; deterministic validation and budgets always decide the exit. See the root [consumer CI instructions](../../README.md#turnkey-ci-for-another-godot-project).

In GitHub Actions, the authoritative gate step prints each measured value beside its threshold. Failed deterministic rules also appear as check annotations, and the job summary contains a result table plus artifact guidance. Accepted or deterministic-fallback AI text appears only in a clearly non-authoritative summary section. Download the artifact for unchanged canonical JSON, raw captures, sanitized logs, and manifests. Presentation failures are warnings and cannot change the saved deterministic exit.

A JSON file is not sufficient evidence when the measured scene failed to load. Review the sanitized Godot logs and require zero script parse/load errors before accepting a capture. The reusable workflow's capture helper enforces this by failing with `godot_script_error`, preserving diagnostics, and withholding affected captures from validation and budgets.

Schema v3 adds opt-in pull-request comparison through `compare-with-base: true`. Merge the v3 policy first while comparison remains false, then enable comparison in a later pull request. The workflow reads policy from the protected base revision and captures three baseline plus three candidate runs with identical settings. It stages candidate evidence and, only in comparison mode, baseline evidence into a normalized runner-temporary directory before upload. This keeps `project-path: .` and nested project paths out of artifact glob construction. This mode doubles capture work; sequential execution on one runner reduces host variation but cannot guarantee identical thermal, scheduling, or system-load conditions.

If the project does not yet have a reviewed budget, call the reusable workflow manually with `mode: calibrate`, `calibration-runs: 5`, `compare-with-base: false`, and `investigate: never`. Calibration is accepted only on the consumer repository's default branch. It uploads a reviewable schema-v3 proposal and calibration report; it does not enforce, edit, or commit policy and receives no AI secret. Download and review the proposal, apply it explicitly with `tools/calibrate_budgets.py --apply-proposal`, commit the v3 policy while comparison remains disabled, and enable protected-base comparison in a later pull request. The root [calibration instructions](../../README.md#calibrate-a-consumer-budget) document the formulas and commands.

Hosted calibration was verified once in PluginTest with five clean 600-sample captures and a fourteen-file artifact. The workflow skipped investigator dependencies, policy enforcement, protected-base capture, and AI. That proof verifies workflow behavior, not the suitability of its proposed thresholds for another project or host.
